# متطلبات واجهة المستخدم وتجربة المستخدم (UI/UX Requirements)

**اسم المشروع:** VELORA (فيلورا)  
**النوع:** منصة ويب متعددة المستأجرين لإدارة مراكز التدريب  
**الإصدار:** 1.0.0  
**الحالة:** معتمد بناءً على المقابلة الأولية  
**اللغة الأساسية للتطبيق:** English  
**التوافق:** متجاوب مع الشاشات من 360px حتى 4K  

---

## 1. الهدف العام

يهدف هذا المستند إلى توثيق متطلبات هيكلة المعلومات، والتنقل، والتخطيط، والحالات التفاعلية لواجهة مستخدم منصة VELORA، مع الالتزام التام بـ [PRD.md](../PRD.md) ومخططات حالات الاستخدام المتاحة.

## 2. استراتيجية المعلومات والتنقل (Information Architecture & Navigation)

### 2.1 مبدأ التنقل المعتمد

يعتمد التطبيق مبدأ **قائمة تنقل رئيسية مشتركة بين جميع الأدوار**، مع تطبيق صلاحيات الوصول بناءً على دور المستخدم (`Role-Based Access Control - RBAC`).

- **قائمة مشتركة**: يتم استخدام نفس بنية التنقل لجميع الأدوار (`Manager`, `Sales`, `Instructor`, `Student`).
- **إخفاء انتقائي**: يتم إخفاء عناصر القائمة الرئيسية غير المصرح بالدور بالوصول إليها، دون إظهارها معطلة أو غير قابلة للنقر.
- **عناصر عامة دائمة الظهور**: تبقى بعض العناصر ظاهرة للجميع في شريط الرأس العلوي بغض النظر عن الدور.
- **توجيه حسب الدور**: عند النقر على "لوحة التحكم"، يتم توجيه المستخدم تلقائياً إلى لوحة التحكم المخصصة لدوره.

### 2.2 شريط الرأس العلوي (Header / Top Bar)

يجب أن يحتوي شريط الرأس العلوي على العناصر التالية، وجميعها **ظاهرة دائمًا لجميع الأدوار**:

| العنصر | الغرض | ملاحظات |
| :--- | :--- | :--- |
| **شعار التطبيق (Logo)** | تعريف بالمنصة | يؤدي النقر عليه إلى لوحة التحكم الخاصة بالدور الحالي. |
| **لوحة التحكم (Dashboard)** | الوصول السريع للوحة التحكم | يظهر لجميع الأدوار، ويُوجّه إلى: `Manager Dashboard` / `Sales Dashboard` / `Instructor Dashboard` / `Student Dashboard` حسب دور المستخدم. |
| **الإشعارات (Notifications)** | عرض التنبيهات الهامة | يظهر لجميع الأدوار. المحتوى يختلف حسب الدور (مواعيد الواجبات، مواد جديدة، تحديثات المدفوعات، طلبات موافقة، إلخ). |
| **قائمة المستخدم (User Menu)** | الوصول للخيارات الشخصية | تحتوي على: `الملف الشخصي (Profile)`، `الإعدادات (Settings)`، `تسجيل الخروج (Logout)`. تظهر دائمًا لجميع الأدوار. |

## 3. هيكل القائمة الجانبية حسب الدور (Role-Based Sidebar)

تم الاعتماد على **قائمة جانبية واحدة مشتركة** يتم تصفيتها ديناميكيًا حسب صلاحيات كل دور، مستندًا إلى أقسام PRD 5، 10، 12 و15.

### 3.1 مدير المركز (Center Manager)

يملك صلاحيات إدارية شاملة ضمن نطاق مركزه فقط.

| عنصر التنقل | مسار مقترح (لأغراض التوجيه فقط) | ملاحظات |
| :--- | :--- | :--- |
| **لوحة التحكم** | `/manager/dashboard` | ملخص عام: الدورات النشطة، الطلاب، المدربين، الإيرادات المحصلة، المستحقات، أرصدة الطلاب المتأخرة. |
| **الدورات (Courses)** | `/manager/courses` | إنشاء، تعديل، تعيين مدربين، جدولة الجلسات، أرشفة الدورات. |
| **المدربين (Instructors)** | `/manager/instructors` | إدارة المدربين، نماذج التعويض (`Fixed`, `PercentageOfCollectedRevenue`, `PerSession`)، متابعة المستحقات. |
| **الطلاب (Students)** | `/manager/students` | دليل الطلاب، ملفات الطلاب، حالة التسجيل. |
| **التسجيلات (Enrollments)** | `/manager/enrollments` | إدارة التسجيل، الخصومات، قوائم الانتظار. |
| **المدفوعات (Payments)** | `/manager/payments` | موافقة/رفض سندات القبض، متابعة التحصيل، تتبع الفائض والاستردادات. |
| **مستحقات المدربين (Instructor Dues)** | `/manager/instructor-dues` | تسوية المدفوعات، حالة التسوية (`Pending`, `PartiallyPaid`, `Paid`, `Adjusted`). |
| **التقارير (Reports)** | `/manager/reports` | تقارير تشغيلية ومالية مختصرة. |
| **المستخدمين والموظفين (Staff & Users)** | `/manager/staff` | إدارة حسابات `Manager` / `Sales` / `Instructor`. |
| **سجل التدقيق (Audit Log)** | `/manager/audit` | عرض سجلات الإجراءات الهامة والمعاملات المالية. |

### 3.2 مسؤول المبيعات والمتابعة (Sales Specialist)

مقيد بالمهام التجارية والتسجيل والتحصيل فقط، ويُحظر عليه الوصول للواجبات، التغذية الراجعة، ومستحقات المدربين.

| عنصر التنقل | مسار مقترح (لأغراض التوجيه فقط) | ملاحظات |
| :--- | :--- | :--- |
| **لوحة التحكم** | `/sales/dashboard` | متابعة المتدربين قيد المتابعة، الدفعات المعلقة، التسجيلات غير المكتملة. |
| **الطلاب (Students)** | `/sales/students` | البحث السريع، إضافة ملف طالب جديد، عرض البيانات الأساسية. |
| **التسجيلات (Enrollments)** | `/sales/enrollments` | تسجيل الطلاب في الدورات النشطة، تطبيق الخصومات المصرح بها، إدارة قوائم الانتظار. |
| **المدفوعات (Payments)** | `/sales/payments` | تسجيل سندات القبض اليدوية (`Cash`, `Bank Transfer`, `POS Card`, `Cheque`) مع انتظار موافقة المدير. |

### 3.3 المدرب الأكاديمي (Course Instructor)

مقيد بالدورات المسندة إليه فقط.

| عنصر التنقل | مسار مقترح (لأغراض التوجيه فقط) | ملاحظات |
| :--- | :--- | :--- |
| **لوحة التحكم** | `/instructor/dashboard` | الدورات المسندة، الجلسات القادمة، الواجبات قيد المراجعة، عدد التسليمات. |
| **دوراتي (My Courses)** | `/instructor/courses` | دخول لمساحة كل دورة على حدة. |
| **الجلسات والحضور (Sessions & Attendance)** | `/instructor/attendance` | جدولة الجلسات، تسجيل الحضور (`Present` / `Absent`)، تصحيح الحضور السابق عند الحاجة. |
| **المواد التعليمية (Materials)** | `/instructor/materials` | رفع وعرض مواد المحاضرات للمتدربين المسجلين بالدورة. |
| **الواجبات والتسليمات (Tasks & Submissions)** | `/instructor/tasks` | إنشاء الواجبات، مراجعة التسليمات، تفعيل استثناء التسليم المتأخر، تقديم ملاحظات. |
| **التغذية الراجعة (Feedback)** | `/instructor/feedback` | إرسال ملاحظات تقييم فردية خاصة لكل طالب. |
| **مستحقاتي (My Earnings)** | `/instructor/earnings` | عرض المستحقات حسب نموذج التعويض، المبالغ المسددة، الرصيد المتبقي. |

### 3.4 المتدرب المسجل (Enrolled Student)

مقيد بالدورات التي لديه تسجيل نشط أو مكتمل فقط.

| عنصر التنقل | مسار مقترح (لأغراض التوجيه فقط) | ملاحظات |
| :--- | :--- | :--- |
| **لوحة التحكم** | `/student/dashboard` | نظرة سريعة على الدورات، الواجبات القادمة، الحضور، الرصيد المالي. |
| **دوراتي (My Courses)** | `/student/courses` | قائمة الدورات المسجل بها مع الوصول لصفحة الدورة. |
| **المواد التعليمية (Materials)** | `/student/materials` | تحميل المواد المسموح بها حصريًا للدورات المسجل بها. |
| **الواجبات (Tasks)** | `/student/tasks` | عرض الواجبات، رفع التسليم، استبدال الملف قبل الموعد النهائي، متابعة حالة التسليم. |
| **الحضور (Attendance)** | `/student/attendance` | عرض سجل الحضور والغياب ونسبة الحضور الخاصة به. |
| **التغذية الراجعة (Feedback)** | `/student/feedback` | عرض الملاحظات الفردية الخاصة به فقط. |
| **المدفوعات والرصيد (Payments & Balance)** | `/student/payments` | عرض كشف المدفوعات، المبلغ الإجمالي، الخصم، المدفوع، المتبقي، وحالة السداد. |

## 4. تخطيط الصفحة (Layout Structure)

### 4.1 البنية العامة

سيتم اعتماد تخطيط ثابت يتكون من:

```
[Header - ثابت في أعلى الصفحة، يظهر للجميع]
├── [Sidebar - قائمة جانبية، مشتركة ومُفلترة حسب الدور]
└── [Main Content Area - محتوى الصفحة حسب الدور والإجراء]
```

### 4.2 سلوك التخطيط

| عنصر | السلوك |
| :--- | :--- |
| **Header** | ثابت، يحتوي على الشعار، Dashboard، الإشعارات، وقائمة المستخدم. |
| **Sidebar** | قابل للطي على الشاشات الصغيرة (`collapsible`) للحفاظ على مساحة المحتوى. |
| **Main Content** | يدعم التمرير عموديًا، ويعتمد على شبكة متجاوبة (`grid/flex`). |
| **Mobile Viewport (>=360px)** | يتحول Sidebar إلى قائمة منزلقة (`off-canvas`) عند الضغط على زر القائمة. |

## 5. تسلسل المحتوى وأولوية العرض (Content Hierarchy)

يجب أن يتبع كل قالب صفحة التسلسل التالي:

1. **عنوان الصفحة (Page Header)** – عنوان واضح يصف الصفحة الحالية.
2. **إجراءات سريعة (Primary Actions)** – الأزرار الأكثر استخدامًا حسب الدور (مثال: "إضافة طالب"، "تسجيل دفعة"، "إنشاء واجب").
3. **ملخصات سريعة (Summary Cards)** – مؤشرات رئيسية ذات صلة بالصفحة.
4. **المحتوى الرئيسي (Data Tables / Forms)** – الجداول، النماذج، القوائم، أو تفاصيل الدورة.
5. **معلومات مساعدة أو تنبيهات (Contextual Alerts)** – تحذيرات، تنبيهات الفائض، أو تذكيرات المرتبطة بالإجراء.

## 6. النماذج، التفاعلات، وحالات النظام (Forms, Interactions & States)

### 6.1 النماذج (Forms)

| متطلب | توضيح |
| :--- | :--- |
| **التحقق الفوري (Inline Validation)** | يتم التحقق من الحقول المطلوبة وصيغ البيانات مباشرةً قبل الإرسال. |
| **رسائل خطأ واضحة** | رسائل قصيرة ومحددة بالعربية/الإنجليزي حسب سياق الصفحة، دون كشف معلومات حساسة. |
| **حقول حساسة** | في المدفوعات يجب توضيح `Amount`, `Payment Method`, `Receipt Reference` بوضوح. |
| **منع الإرسال المكرر** | تعطيل زر الإرسال بعد الضغط مع عرض مؤشر التحميل لمنع التكرار. |

### 6.2 حالات النظام المطلوبة

يجب دعم الحالات التالية في القوائم، الجداول، والصفحات:

| الحالة | متى تستخدم | متطلبات العرض |
| :--- | :--- | :--- |
| **Loading** | أثناء جلب البيانات | هيكل تحميل (`Skeleton Loader`) مناسب لنوع المحتوى (جدول / بطاقة). |
| **Empty State** | لا توجد بيانات لعرضها | رسالة توضيحية + أيقونة + إجراء مناسب (مثال: "لا توجد دورات بعد" مع زر "إنشاء دورة" للمدير). |
| **Error State** | فشل الطلب | رسالة خطأ واضحة، زر "إعادة المحاولة" عند الإمكان. |
| **Success State** | بعد تنفيذ إجراء ناجح | إشعار نجاح واضح (`Toast/Inline Alert`) يظهر لفترة قصيرة. |
| **No Permission** | محاولة وصول غير مصرح به | عرض حالة مناسبة مع زر للعودة للوحة التحكم دون كشف تفاصيل حساسة. |

### 6.3 تفاعلات رئيسية

| التفاعل | وصف |
| :--- | :--- |
| **التصفية والبحث** | متوفر في القوائم الكبيرة (الطلاب، المدفوعات، التسجيلات) مع إمكانية التصفية حسب الحالة/الدورة. |
| **الجداول** | استخدام جداول واضحة مع ترقيم الصفحات (`Pagination`)، وأولوية للقراءة على الجوال. |
| **التأكيدات** | عرض نافذة تأكيد قبل الإجراءات الحساسة (أرشفة دورة، اعتماد/رفض سند قبض، تفعيل استثناء تسليم متأخر). |
| **معاينة سريعة** | قدر الإمكان استخدام نوافذ جانبية (`Drawer/Modal`) لتفادي الانتقال الكامل للصفحة عند الإجراءات السريعة. |

## 7. الاستجابة، الوصولية، والهوية البصرية (Responsive, Accessibility & Branding)

### 7.1 الاستجابة (Responsive Design)

| نطاق الشاشة | توجيه التنفيذ |
| :--- | :--- |
| **Mobile (360px – 640px)** | إخفاء Sidebar وتحويله لقائمة منزلقة، تحويل الجداول إلى بطاقات (`Card List`)، الحفاظ على أزرار الإجراءات قابلة للمس. |
| **Tablet (641px – 1024px)** | دعم طي Sidebar، الحفاظ على قابلية القراءة، ترتيب العناصر عموديًا عند الحاجة. |
| **Desktop (1025px+)** | عرض Sidebar كاملًا + Header ثابت + أقصى استفادة من المساحة مع الحفاظ على سهولة المسح البصري. |

### 7.2 الوصولية (Accessibility)

| متطلب | توضيح |
| :--- | :--- |
| **التنقل بالكيبورد** | قابلية التنقل بين العناصر والتركيز الظاهر (`Focus States`) واضح. |
| **نصوص بديلة** | إضافة `alt-text` للصور والأيقونات ذات المعنى. |
| **تباين الألوان** | الحفاظ على تباين كافي للنصوص والأزرار لقراءة مريحة. |
| **التسميات الواضحة** | استخدام تسميات واضحة لحقول النماذج وأزرار الإجراءات. |
| **دعم قارئات الشاشة** | استخدام عناصر دلالية مناسبة (`<header>`, `<nav>`, `<main>`, `<aside>`) حيثما أمكن. |

### 7.3 الهوية البصرية (Brand Identity)

| عنصر | توجيه |
| :--- | :--- |
| **اسم التطبيق** | `VELORA` (فيلورا) |
| **شعار التطبيق** | يظهر في أعلى Sidebar/Header، بسيط وواضح. |
| **نمط عام** | واجهة نظيفة، احترافية، موجهة للعمليات الإدارية اليومية مع أقل تشتيت ممكن. |
| **اللغة** | التطبيق بالأساس إنجليزي كما ورد في PRD، مع إمكانية دعم محتوى ثنائي اللغة مستقبلاً دون تغيير هيكل التنقل. |

## 8. قواعد ربط مع متطلبات PRD

| مرجع PRD | تطبيق في UI/UX |
| :--- | :--- |
| **القسم 5 & 6 (الأدوار والشخصيات)** | توزيع العناصر حسب كل شخصية مع تقييد الوصول بدقة. |

| **القسم 15 (Roles & Permissions)** | إخفاء عناصر القائمة حسب الصلاحيات، وحجب الوصول للبيانات غير المسموح بها. |
| **القسم 10 Features (Attendance, Tasks, Payments, Instructor Dues)** | إدراج أقسام `Attendance`، `Tasks & Submissions`، `Payments`، `Instructor Dues` في القائمة حسب الدور فقط. |
| **القسم 9 MVP Scope** | التركيز على الوظائف الأساسية فقط، وعدم إضافة عناصر غير مدرجة ضمن النطاق. |

## 9. ملخص نهائي

- **بنية موحدة**: قائمة تنقل رئيسية مشتركة مع فلترة حسب الدور.
- **رأس علوي ثابت**: `Dashboard` + `Notifications` + `User Menu (Profile/Settings/Logout)` تظهر لجميع المستخدمين.
- **توجيه ذكي**: لوحة التحكم مخصصة لكل دور ومُوجّه تلقائياً.
- **أمان بالواجهة**: إخفاء العناصر غير المصرح بها، مع الاعتماد على التحقق الصارم على الخادم.
- **متجاوب وسهل الاستخدام**: يدعم الجوال، ويعطي أولوية للعمليات الأكثر تكرارًا حسب كل دور.
- **متوافق مع PRD**: جميع التوجيهات أعلاه مستمدة مباشرة من متطلبات VELORA المعتمدة.
